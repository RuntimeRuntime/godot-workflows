# D2-08 — Choose physics body and movement authority

When: Author a controllable character, simulated object, fixed obstacle, moving platform, door or projectile with collisions.

Native candidates: `CharacterBody2D`, `RigidBody2D`, `StaticBody2D`, `AnimatableBody2D`, `CollisionShape2D`, `CollisionPolygon2D`.

## Approach

Use CharacterBody2D when code owns movement/collision response; move in `_physics_process()` with `move_and_slide()` for common sliding platformer/top-down behavior or `move_and_collide()` when custom response is needed. Use RigidBody2D when forces and the physics simulation own motion. Use StaticBody2D for fixed environment and AnimatableBody2D for manually/animation-moved platforms or doors that should affect other bodies.

Do not write a custom collision solver for normal character motion or directly move a physics body with transform updates when the matching native body and movement API meet the requirement. Custom kinematics remain justified for a specific nonstandard mechanic.

## Pitfalls

- CharacterBody2D is not moved by gravity/friction automatically; calculate its motion and use its movement API instead of setting position.
- RigidBody2D is simulation-owned; changing position/velocity ad hoc can produce unexpected behavior. Use forces and `_integrate_forces()` when direct physics-state control is needed.
- AnimatableBody2D's sync-to-physics mode is useful for AnimationPlayer-driven moving platforms and should not be combined with `move_and_collide()`.
- Physics body movement belongs in the physics callback; test collision layers/masks and body response, not only the sprite.

## Verify

- Use visible collision shapes and exercise walls, slopes, ledges, moving platforms and the intended response.
- Check physics layers/masks against the named project layer policy and test both expected contacts and non-contacts.
- Verify movement remains stable under the target physics tick rate and after save/reopen of body/shape resources.
- For designed grace, buffering or cooldown, test accepted and expired boundaries, one-time consumption and reset at declared physics timing; observe feel separately. Window lengths and the presence of coyote time are game choices. Distinguish the movement body from the sensor roles in [overlap filtering](D2-09.md).

## Version and limits

Godot 4.7 has distinct 2D body classes. Do not mechanically substitute 3D nodes/APIs; mirror the requirement with a 2D example and current class docs.
