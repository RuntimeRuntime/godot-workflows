# SH-09 — Project Resources versus external runtime files

When: Imported project assets, user-generated files, mods, downloads, or custom runtime-loaded media.

Native candidates: `Resource`, `ResourceLoader`, `FileAccess`, `Image`, `ImageTexture`, `AudioStream`.

## Approach

Use Godot's Resource/import pipeline for project assets and FileAccess for ordinary user data. Use runtime external-file loading only when the product supports external/user-provided content.

Do not load project resources through raw OS paths or external-file APIs when ResourceLoader/import behavior is intended; do not assume arbitrary user formats/platform paths work.

## Pitfalls

- res:// becomes read-only in exported projects.
- Runtime external file loading bypasses resource handling such as translation remaps.
- Export filters may be needed for non-resource data files.

## Verify

- Run an exported build against the intended project/data path.
- Cover missing/unsupported/malformed external content if accepted.

## Version and limits

Godot 4.7 docs; external formats and filesystem access vary by target.

Untrusted content or security-sensitive protocols require the threat-/protocol-specific follow-up in [discovery](../discovery.md). A topic match does not discharge it. Trusted project-authored assets do not automatically activate that branch.
