# SH-07 — Accessibility-aware Control behavior

When: Accessibility requirements include screen reader, keyboard/controller use, scaling, or existing access settings.

Native candidates: `Control.accessibility_name`, `Control.accessibility_description`, `Control.accessibility_flow_to_nodes`, `Control.focus_neighbor_*`, `Theme`.

## Approach

Use focus/navigation properties, visible focus styling, scalable themes, accessibility names/descriptions and flow/label relations where needed. Godot 4.7 documents AccessKit integration for Windows/macOS/Linux.

Do not treat engine support as complete accessibility coverage or hide focus visuals; platform-specific requirements may require additional work.

## Pitfalls

- Labels and logical spoken order require authoring.
- Documented screen-reader platforms do not establish coverage on every export target.
- Engine support does not replace user testing with target assistive technology.

## Verify

- Use target screen reader/accessibility tools and keyboard/controller navigation.
- Check labels, order, live updates, focus visibility, and UI scale.
- Record unavailable target observation as blocked/limited evidence.

## Version and limits

Godot 4.7 docs; conditional applicability, not a standing gate for every offline feature.
