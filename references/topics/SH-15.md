# SH-15 — Export presets and platform feature checks

When: Exporting, OS-specific APIs, non-resource assets, platform-specific input/audio/network/accessibility, or renderer/format constraints.

Native candidates: `ExportPreset`, `OS.has_feature`, `ProjectSettings`, `ResourceUID`.

## Approach

Inspect project export presets, templates, resource filters and platform permissions; use case-sensitive OS feature tags only for distinctions they actually represent, then test the target build.

Do not treat editor play as proof of export support, assume resource inclusion for every data file, or use a feature tag instead of an actual OS capability check where needed.

## Pitfalls

- Some files require non-resource export filters.
- Feature tags are not equivalent to runtime device capabilities in all contexts; web-on-mobile has web_<platform> tags.
- Export templates/SDK permissions and platform support vary.

## Verify

- Build and run the nominated preset.
- Inspect packaged content/permissions and exercise target-sensitive behavior.

## Version and limits

Godot 4.7 docs; target set and renderer are project-specific; this remains conditional.

## Primary sources


- [FS31: Exporting projects](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_projects.html). Scope/limits: Per-platform requirements are described in each platform export guide and can change by version.

- [FS32: Feature tags](https://docs.godotengine.org/en/4.7/tutorials/export/feature_tags.html). Scope/limits: Runtime feature tags are not a substitute for a platform API capability query or target-device verification.
