# ED-01 — Editor extensions, Inspector integration and undo history

When: Repeated authoring operations or specialized editable content need a native editor workflow.

Native candidates: `EditorPlugin`, `EditorInspectorPlugin`, `EditorProperty`, `EditorUndoRedoManager`.

## Approach

Choose an editor extension appropriate to the task and integrate custom property controls and undo history with Godot instead of building an unrelated authoring interface.

One-off editor modifications that bypass maintainable Inspector authoring or leave no recoverable state.

## Pitfalls

- Register and remove plugin contributions during enable/disable.
- Editor property widgets must communicate changes and refresh external changes.
- Undo history may be scene-specific or global; context must match the edited content.

## Verify

- Enable/disable without leaked controls or duplicate registrations.
- Undo/redo and save/reopen the affected content.
- Exercise editor/game separation and actual Inspector tuning effect.

## Version and limits

Godot 4.7 documentation; no runtime validation.

Specialist/target behavior needs project-specific research and calibration; also read [coverage boundaries](../discovery.md).
