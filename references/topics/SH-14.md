# SH-14 — Autoloads and global services

When: State or service must survive scene changes and be available across unrelated scenes.

Native candidates: `Autoload Node`, `SceneTree`, `Signal`, `Resource`, `static func`, `static var`.

## Approach

Prefer scene-local nodes, signals/dependency injection, shared Resources or static helpers when suitable; use a narrow Autoload for genuinely broad-lived owned state/services.

Do not centralize unrelated state in a global manager or assume Autoload is an engine-enforced singleton; global access remains a deliberate project choice.

## Pitfalls

- Hidden global access expands debugging/ownership boundaries.
- Autoloaded nodes survive scene changes and may preserve state unexpectedly.
- Autoload can be instantiated separately; singleton uniqueness is not enforced.

## Verify

- Run scenes independently and across transitions; confirm state lifetime/reset and expected dependencies.

## Version and limits

Godot 4.7 best-practices guidance; architecture exceptions remain valid when justified.
