# SH-12 — HTTP services versus gameplay networking

When: Backend calls, HTTP downloads/uploads, or service APIs; multiplayer gameplay is handled separately.

Native candidates: `HTTPRequest`, `HTTPClient`, `TLSOptions`, `JSON`.

## Approach

Use HTTPRequest and its completion signal for normal asynchronous HTTP(S) calls. Use HTTPClient only when lower-level polling/connection control is required; use Godot multiplayer facilities for gameplay synchronization.

Do not block the main loop, issue simultaneous requests through one HTTPRequest, trust response data, or put sensitive data in GET URLs.

## Pitfalls

- Android export requires INTERNET permission.
- Web requests are subject to CORS.
- TLS/platform support and response size/errors need consideration.

## Verify

- Cover success, HTTP errors, connection failure, malformed response and cancellation.
- Verify actual target export and service security behavior.

## Version and limits

Godot 4.7 HTTPRequest class docs; HTTPClient tutorial is labeled WIP/outdated in stable docs.

Untrusted content or security-sensitive protocols require the threat-/protocol-specific follow-up in [discovery](../discovery.md). A topic match does not discharge it. Trusted project-authored assets do not automatically activate that branch.
