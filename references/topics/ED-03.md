# ED-03 — Native runtime inspection and debugging aids

When: Collision, pathing, scene state or target behavior is unclear during diagnosis.

Native candidates: `Godot Debugger`, `Remote scene tree`, `Visible collision/navigation/avoidance overlays`, `Multiple run instances`.

## Approach

Use engine runtime inspection and relevant overlays before constructing bespoke debugging machinery.

Treating a static scene or console-only trace as the complete running state.

## Pitfalls

- Remote inspection concerns the running instance.
- Hot-reload/network-filesystem deployments are not the same as a standalone target package.
- Debug instrumentation can affect measurements.

## Verify

- Identify the running scene/revision and capture the relevant overlay/state.
- Repeat the failing interaction with the actual target or required multiple instances.
- Separate diagnostic instrumentation from representative measurements.

## Version and limits

Godot 4.7 documentation; no runtime validation.

Specialist/target behavior needs project-specific research and calibration; also read [coverage boundaries](../discovery.md).

## Primary sources


- [FD10: Overview of debugging tools](https://docs.godotengine.org/en/4.7/tutorials/scripting/debug/overview_of_debugging_tools.html). Scope/limits: Runtime overlays, remote scene inspection and multi-instance descriptions inspected; no debugger connection.
