# D2-12 — 2D lights, shadows and occlusion

When: Add real-time 2D light, ambient darkening, cast shadows, normal-map depth or tile/particle occlusion.

Native candidates: `CanvasModulate`, `PointLight2D`, `DirectionalLight2D`, `LightOccluder2D`, `CanvasTexture`, `TileSet`, `TileMapLayer`.

## Approach

Use CanvasModulate for unlit ambient color, PointLight2D for local sources and DirectionalLight2D for sun/moon direction. Add LightOccluder2D polygons or TileSet occlusion polygons where shadows should be cast; use CanvasTexture normal/specular maps only when the art needs directional surface response.

Use built-in Light2D, occluder and CanvasTexture workflows for ordinary 2D lighting before writing a full-screen light/shadow renderer. Additive sprites are a cheaper visual effect but are not equivalent to lighting or shadow casting.

## Pitfalls

- Lights brighten the existing unshaded canvas; without CanvasModulate, the scene can look fully lit even away from lights.
- Shadows require valid occluder polygons; having a light alone does not create shadows.
- 2D lights/shadows render at viewport pixel resolution. Nearest texture filtering alone does not make lighting pixelated.
- Large light textures and soft shadow filters can raise rendering cost; directional shadows have documented method limitations.

## Verify

- Inspect light masks, Z/layer ranges, occluder outlines and intended receiver textures in the editor.
- Run with actual renderer and viewport resolution; test dark areas, overlapping lights, shadows and any normal maps.
- For pixel art or performance-sensitive targets, compare the actual output/cost; do not assume texture filtering changes light resolution.

## Version and limits

Godot 4.7 supports CanvasItem lighting/shadows and normal maps. Pixel-lighting custom shader guidance is a specialized follow-on, not a universal requirement.
