# D3-05 — Physics body role and collision-shape composition

When: An object needs collision, overlap detection, physical influence, or physical motion.

Native candidates: `StaticBody3D`, `AnimatableBody3D`, `RigidBody3D`, `CharacterBody3D`, `Area3D`, `CollisionShape3D`, `Shape3D`, `Joint3D`.

## Approach

Select body by motion ownership; assign Shape3D resources through direct CollisionShape3D children, configure collision layers/masks, and use specialized joints/VehicleBody3D/SoftBody3D only when the game asks for those mechanics.

Prefer native physics bodies, areas and shape resources when their documented semantics fit.

## Pitfalls

- Visual mesh is not automatically a suitable production collider.
- Indirect CollisionShape3D descendants may be ignored.
- Concave and primitive shape performance differs.
- Physics defaults and support can vary by backend.

## Verify

- Show debug collision shapes.
- Check layers/masks and scale.
- Exercise contact and overlap in the target backend.

## Version and limits

4.7 physics docs; verify selected physics engine and any specialist class support.
