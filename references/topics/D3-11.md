# D3-11 — Imported skeletal animation and layered control

When: A character or object uses imported skeletal clips, blending, state transitions, IK, retargeting, or bone constraints.

Native candidates: `Skeleton3D`, `Skin`, `MeshInstance3D`, `AnimationPlayer`, `AnimationLibrary`, `AnimationTree`, `SkeletonModifier3D`.

## Approach

Preserve imported skin/skeleton/animation relationships; use AnimationPlayer as clip source and AnimationTree as optional transition/blend controller; add SkeletonModifier3D family for supported bone modification needs.

Use imported animation libraries and built-in animation/skeleton controls before copying clips or writing a bespoke blend/IK layer.

## Pitfalls

- AnimationTree references an AnimationPlayer; it does not contain clips.
- Reimport can replace imported data.
- Bone global pose is skeleton-relative, not world-space.
- Blended properties need deliberate reset/rest values.

## Verify

- Inspect clip names/tracks and Skin binding.
- Test reset pose and one blend/transition at runtime.
- Reimport and reopen the composition.

## Version and limits

4.7 importer, AnimationTree, Skeleton3D and SkeletonModifier3D APIs.
