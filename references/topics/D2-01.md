# D2-01 — Grid worlds: TileSet, atlas and TileMapLayer

When: Author or change a fixed grid-based level, repeated tile world, isometric/hex map, or tile layer.

Native candidates: `TileMapLayer`, `TileSet`, `TileSetAtlasSource`, `TileData`, `TileMapPattern`.

## Approach

In 4.7, build a TileSet from one or more atlas sources in the TileSet editor, set its cell shape/layout/size to match the art, save the TileSet as an external Resource when levels reuse it, and paint the level in one TileMapLayer per visual/semantic layer. Use the TileMap editor's saved patterns for reusable painted chunks.

Do not place thousands of Sprite2D nodes or write a bespoke grid painter/cell serialization layer when ordinary painted grid content is sufficient. Procedural maps and non-grid layouts remain valid when requirements call for them.

## Pitfalls

- TileMap is deprecated in 4.7; TileMapLayer contains one layer, so compose maps with several nodes.
- Removing a used TileSet tile or changing identifiers can leave invalid cell references; inspect the TileSet editor's missing-tile placeholders.
- A layer reorder is different from deleting a layer; deleting it removes its painted cells.
- TileMapLayer serialized cell coordinates have a signed 16-bit range; check the class reference for exceptionally large maps.
- An atlas cell can be valid yet contain only part of a motif or an unintended transparent region. Identify complete composite footprints and intended top/side/bottom caps from the actual artwork.
- In Godot 4.7, `TileMapPattern.set_cell` defaults `alternative_tile` to -1. Supply the intended valid alternative explicitly (often 0); preserve deliberate erase cells as an explicit pattern choice.

## Verify

- Save and reopen the level; inspect the active layer and TileSet assignments, representative cells, patterns and visual order.
- Run the scene and verify representative cell rendering/collision at the intended viewport scale.
- For any migration, confirm old TileMap data and all layers survived conversion.
- For a repeated motif, stamp a representative complete pattern, save/reopen and inspect its entire footprint at game scale, including edge/corner/isolated caps. Confirm intended painted cells are nonempty and reference valid source/atlas/alternative IDs; a loop over zero cells proves nothing.
- Keep fixed actors/pickups named and selectable. Check their relevant visual/collision footprint against solids and declared decoration exclusions across the authored set where practical. Record intentional hidden rewards, cropping, overlap or procedural exceptions.

## Version and limits

Godot 4.7 documents TileMapLayer as the replacement for deprecated TileMap. For Godot 3 or earlier 4.x, inspect migration notes and project behavior; do not upgrade an existing game automatically.
