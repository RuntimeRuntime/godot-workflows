# D2-11 — Camera, coordinates, parallax and 2D draw ordering

When: Add camera following/limits/smoothing, convert pointer/world coordinates, scroll backgrounds, sort top-down overlap or compose layered 2D scenes.

Native candidates: `Camera2D`, `Parallax2D`, `CanvasLayer`, `CanvasItem`, `Node2D`, `Transform2D`, `Viewport`, `SubViewport`, `InputEventMouseButton`, `InputEventMouseMotion`, `TileMapLayer`, `Sprite2D`.

## Approach

Treat Node2D.position/transform as parent-local; use local/global conversion methods when moving between nested objects or query spaces. Distinguish item, parent-item, canvas/world, viewport and window/screen coordinates, accounting for camera and viewport stretch transforms. Use CanvasLayer for an independent canvas: by default it stays fixed on screen, enable follow-viewport behavior when it should track the world, and create one per viewport. Use Camera2D for viewport follow, zoom, drag margins, limits and smoothing. Use Parallax2D for layers that scroll at different rates; Godot 4.7 recommends it over ParallaxLayer/ParallaxBackground. Use CanvasItem Y-sort for objects whose front/back order follows world Y and Z index for explicit local ordering; set TileMapLayer Y-sort origin when its tile baseline differs.

Prefer the built-in camera limits/smoothing and Parallax2D repeat behavior over custom camera offset and background-scroll scripts for ordinary follow/parallax. Use a custom camera only for behavior the native node cannot express.

## Pitfalls

- Node2D.position and RayCast2D.target_position are local to their parent/node; do not mix coordinates from different nested transforms or assign a screen/viewport pointer position to a world-space target without converting it.
- Camera2D changes the viewport's default canvas transform. A CanvasLayer does not follow it unless follow-viewport behavior is enabled; each CanvasLayer is bound to one viewport, and duplicate layer indices have non-deterministic order.
- Mouse InputEvent positions are viewport coordinates; in captured-mouse mode, InputEventMouseMotion.position is centered on the screen. Convert pointer coordinates to the intended canvas/world space, and use the documented relative/screen-relative values for captured movement.
- Window stretch and SubViewport/SubViewportContainer transforms add coordinate conversions; a pointer position from one viewport/window cannot be assumed to be another canvas's world coordinate.
- Parallax repeat depends on texture size/placement relative to the repeat canvas; scaling can change coverage, and zooming out can expose gaps.
- Y-sort compares CanvasItems only when the relevant parent relationship and z-index allow sorting; do not assume Z index changes input/event ordering.
- Scene-tree order, Y-sort, Z index and CanvasLayer ordering solve different composition problems; avoid reshuffling hierarchy solely to fix visual order if native ordering properties fit.

## Verify

- Move the camera across level bounds, reverse direction and zoom; check limits, smoothing, seams and repeat gaps.
- Under nested translation/rotation/scale, compare pointer targeting and physics-query results with known world points; verify local/global conversions after camera movement, window stretch and within each SubViewport.
- For mouse targeting, confirm the event's viewport coordinates map to the intended world target after camera motion and viewport stretch; test captured mouse motion with the documented relative/screen-relative values.
- Verify a CanvasLayer both fixed to screen and following the viewport, then test its viewport assignment in split-screen or another SubViewport setup.
- Move overlapping actors past one another and verify Y-sort baseline and exceptional Z/CanvasLayer ordering.
- Save/reopen and inspect camera/parallax properties, then capture the actual game view at target aspect ratio.

## Version and limits

Parallax2D is the recommended 4.7 node; older projects may use ParallaxLayer/ParallaxBackground. Check exact active camera, viewport and canvas-layer setup before changing a legacy scene.
