# SH-03 — InputMap actions, devices, and remapping

When: Adding controls, multiple input devices, per-player bindings, or runtime key remapping.

Native candidates: `InputMap`, `Input`, `InputEvent`, `InputEventAction`.

## Approach

Define named actions and bind device events to them; use action polling for held state and InputEvents for discrete events. Persist runtime remaps explicitly in player settings.

Do not scatter raw key checks through gameplay or assume runtime InputMap state is saved; raw events remain suitable when the feature requires event-specific details.

## Pitfalls

- InputMap runtime changes are not automatically persisted.
- Built-in UI actions should stay separate from gameplay mappings.
- Input events can have device-specific properties and target limits.

## Verify

- Exercise required actions on each nominated device.
- Remap and restart to check settings persistence.
- Confirm UI focus actions remain distinct.

## Version and limits

Godot 4.7 docs; verify physical devices and platform capabilities on target.
