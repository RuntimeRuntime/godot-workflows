# D3-13 — Lighting, Environment and renderer-aware GI

When: A scene needs an authored runtime sky/ambient environment, lights/shadows, post-processing, or indirect illumination.

Native candidates: `WorldEnvironment`, `Environment`, `Camera3D`, `DirectionalLight3D`, `OmniLight3D`, `SpotLight3D`, `AreaLight3D`, `LightmapGI`, `VoxelGI`, `SDFGI`, `ReflectionProbe`.

## Approach

Author runtime WorldEnvironment/lights/materials; select GI based on static/dynamic content and renderer support; inspect project renderer and target hardware before baking or depending on GI.

Prefer supported Environment, Light3D and GI resources before custom render pipelines.

## Pitfalls

- Editor preview sun/sky does not run in game.
- Only one WorldEnvironment may exist per active tree.
- VoxelGI/SDFGI are Forward+ only in 4.7.
- LightmapGI baking/rendering support differs by renderer and baked geometry must match content mobility.

## Verify

- Compare editor and runtime lighting.
- Verify target renderer support and baked-resource update path.
- Check shadows, environment override and target hardware.

## Version and limits

Renderer limits here are documented for 4.7; re-check when renderer or engine version changes.
