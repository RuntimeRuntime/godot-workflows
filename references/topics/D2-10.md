# D2-10 — RayCast2D, ShapeCast2D and direct physics queries

When: Need a line-of-sight, ground probe, aim hit, swept volume, instantaneous query or gameplay decision from collision geometry.

Native candidates: `RayCast2D`, `ShapeCast2D`, `PhysicsDirectSpaceState2D`, `PhysicsRayQueryParameters2D`, `PhysicsShapeQueryParameters2D`.

## Approach

Use RayCast2D for a persistent ray whose result is sampled each physics frame; use a direct-space query from `_physics_process()` for one-off/dynamically configured ray queries; use ShapeCast2D when sweeping a region or checking a wide shape. Configure collision masks and self-exclusions explicitly.

Do not approximate area/shape collision queries with a large number of handwritten point samples when one native shape cast can express the query. A ray is cheaper and clearer than a shape cast when the question truly concerns one line.

## Pitfalls

- RayCast2D caches a result per physics frame; call `force_raycast_update()` after same-frame changes when immediate data is required.
- Direct physics-space access is only safe during `_physics_process()`; a query outside it can encounter a locked space.
- ShapeCast2D sweeps multiple points/objects but costs more than raycasting.
- A ray hitting a TileMapLayer may return the TileMapLayer node, not a PhysicsBody2D; handle collider types and masks accordingly.

## Verify

- Turn on debug visibility and inspect the ray/shape's actual world path and collision mask.
- Test near misses, self-exclusion, initial-overlap, area/body filtering and same-frame updates.
- Assert the reported collider/position against a known geometry fixture and run the query on the intended physics frame.

## Version and limits

RayCast2D and ShapeCast2D semantics are documented in 4.7 class references. Query timing is physics-thread-sensitive; validate with the selected threading configuration.
