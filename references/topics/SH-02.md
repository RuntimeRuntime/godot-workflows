# SH-02 — UI focus and input routing

When: Keyboard/controller UI, modal/menu input, or custom Control input handling.

Native candidates: `Control`, `Node._unhandled_input`, `Control._gui_input`, `InputEvent`.

## Approach

Configure focus modes/neighbors and initial focus; let Controls consume UI events and use unhandled input for gameplay that must wait until the GUI has had its chance.

Do not depend on guessed focus order in complex menus or reuse built-in ui_* focus actions for gameplay; custom event handling remains valid for specialized gestures.

## Pitfalls

- A hidden focused Control may lose focus.
- An open menu can leak input into gameplay if handling is placed too early.
- Focus-neighbor inference can choose an unintended path.

## Verify

- Traverse complete UI flows with keyboard and controller.
- Check focus after modal open/close and hidden controls.
- Confirm UI actions do not trigger gameplay behind the UI.

## Version and limits

Godot 4.7 docs; target device/input configuration remains project-specific.
