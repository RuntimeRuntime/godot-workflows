# SH-01 — Responsive UI layout and theming

When: Authoring a menu, HUD, settings screen, inventory, dialog, or interactive overlay.

Native candidates: `Control`, `Container`, `HBoxContainer`, `VBoxContainer`, `GridContainer`, `MarginContainer`, `Theme`, `StyleBox`.

## Approach

Use Control nodes for conventional UI; choose layout containers for reflowing groups, anchors/offsets for viewport-relative geometry, and Theme resources for reusable appearance.

Do not build a custom layout engine or manually position children owned by a Container; world-space/custom-rendered UI remains a valid exception.

## Pitfalls

- Container layout overrides child positioning.
- Fixed-size assumptions can fail at other resolutions/aspect ratios.
- Theme inheritance follows Control chains and may be locally overridden.

## Verify

- Resize at nominated viewport sizes/aspect ratios.
- Inspect saved layout/theme after reopen.
- Run nominated tuning changes and observe their intended effect.

## Version and limits

Godot 4.7 docs; use project-pinned version and target resolution policy.

## Primary sources


- [FS01: Using Containers](https://docs.godotengine.org/en/4.7/tutorials/ui/gui_containers.html). Scope/limits: Layout examples are illustrative; test target aspect ratios and project UI scale.

- [FS02: Size and anchors](https://docs.godotengine.org/en/4.7/tutorials/ui/size_and_anchors.html). Scope/limits: Does not define a universal project resolution/stretch policy.
