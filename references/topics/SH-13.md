# SH-13 — SubViewport render surfaces

When: Split-screen, minimaps, camera feeds, render-to-texture, or mixing 2D/3D/UI worlds.

Native candidates: `SubViewport`, `SubViewportContainer`, `ViewportTexture`, `Camera2D`, `Camera3D`.

## Approach

Use SubViewport for an isolated render surface; expose it through SubViewportContainer or ViewportTexture; set size and update mode for the scenario.

Do not build a custom render-to-image system for ordinary additional views or assume SubViewport draws by itself or automatically receives input.

## Pitfalls

- A SubViewport needs nonzero size and a display surface/texture.
- Input forwarding is not automatic for standalone SubViewports.
- High-resolution render targets/readbacks can add cost.

## Verify

- Confirm intended camera/world in output texture, deliberate input routing, update mode, listener, and target-resolution performance.

## Version and limits

Godot 4.7 docs; renderer and target performance require project-specific validation.
