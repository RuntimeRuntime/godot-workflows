# D2-04 — 2D image import, filtering and pixel-art quality

When: Import or reuse 2D art, pixel art, sprite sheets, zoomed textures, or shared images also used in 3D.

Native candidates: `Texture2D`, `Sprite2D`, `CanvasItem`, `CanvasTexture`, `AtlasTexture`.

## Approach

Keep source images in the project and use Godot's image import options for compression/mipmaps. Set filtering and repeat on the CanvasItem (or project default); these are not image-import settings in Godot 4. Enable 2D mipmaps only when the project visibly benefits from downscaled/zoomed textures.

Avoid runtime image slicing, custom file-copy/import workflows or per-sprite filtering code when import settings, CanvasItem properties and built-in sprite regions suffice.

## Pitfalls

- Godot 4.7 defaults (Lossless, no mipmaps) are suited to 2D; VRAM compression may visibly damage lower-resolution 2D art, while mipmaps trade roughly one-third more memory for better downscaling.
- Detect 3D can automatically reimport a texture with 3D-oriented compression and mipmaps; a pixel-art asset shared with 3D may need an explicit compression choice.
- Nearest texture filtering does not pixelate real-time 2D lighting/shadows; those are computed at viewport pixel resolution.
- Texture padding and filtering/repeat choices can affect atlas edge bleeding; inspect actual scaled output.

## Verify

- Inspect the Import dock and reimport result for representative assets.
- View the art at intended window size, zoom and renderer; check alpha edges, pixel sharpness and memory-sensitive mipmap choices.
- For a shared 2D/3D texture, confirm both uses retain intended visual quality after import.

## Version and limits

Godot 4 moved filtering/repeat from import options to CanvasItem/per-material settings. Project style and renderer decide the correct values; pixel-art defaults are not universal.
