# D3-12 — 3D navigation: path, actor motion, avoidance and links

When: Actors need routes across baked walkable surfaces, discrete point graphs, local avoidance, or special traversal connections.

Native candidates: `NavigationRegion3D`, `NavigationMesh`, `NavigationAgent3D`, `NavigationObstacle3D`, `NavigationLink3D`, `AStar3D`, `CharacterBody3D`.

## Approach

Bake NavigationMesh on regions; use NavigationAgent3D or NavigationServer for queries; move the parent actor in game code; implement traversal when a NavigationLink3D connection is reached.

Use mesh-based NavigationServer for free movement over areas and AStar3D for discrete weighted graphs; only add avoidance for actors that need it.

## Pitfalls

- NavigationAgent3D does not move its parent.
- Avoidance does not alter pathfinding and is separate from physics/nav geometry.
- Links describe route connections but do not implement jumps/teleports.
- Queries before map synchronization can be empty.

## Verify

- Inspect baked navigation coverage and region connection.
- Test reachable/unreachable route and actor movement.
- Test local obstacle avoidance and every special link traversal.

## Version and limits

4.7 navigation docs; confirm project nav layers, synchronization and avoidance mode.

## Primary sources


- [F3D18: 3D navigation overview](https://docs.godotengine.org/en/4.7/tutorials/navigation/navigation_introduction_3d.html). Scope/limits: Overview setup is minimal and does not certify complex navigation quality.

- [F3D19: Using NavigationAgents](https://docs.godotengine.org/en/4.7/tutorials/navigation/navigation_using_navigationagents.html). Scope/limits: RVO avoidance assumptions can fail in pathological symmetric scenarios; project movement must integrate results.

- [F3D20: Using NavigationLinks](https://docs.godotengine.org/en/4.7/tutorials/navigation/navigation_using_navigationlinks.html). Scope/limits: Link records path connectivity, not animation or traversal mechanics.
